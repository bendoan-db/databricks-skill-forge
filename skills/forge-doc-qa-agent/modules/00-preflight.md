# 00 · Preflight

Find the index the agent will search, resolve the agent's inputs, confirm the tooling, base skills, and permissions, and get a cost go-ahead before anything billable runs. The resolved values go in `<workdir>/doc-qa.json`.

## 1. Find the index

The agent searches an index built by the `forge-unstructured-doc-extraction` skill, described by its `<workdir>/doc-index.json`.

- **No `doc-index.json`:** run `forge-unstructured-doc-extraction` in this `<workdir>` first, through its module 03, with the user's volume. Tell it the index is for this agent, so it keeps `name` to 17 characters or fewer. Then come back here.
- **`doc-index.json` exists:** read it. Its `completed` must include `02-chunk-index`; if it doesn't, resume that skill first. If `03-evaluate` is missing, tell the user that retrieval quality is unmeasured or below its thresholds, and continue only if they agree.
- **An index built another way:** not supported. The search tool and citations depend on the columns `forge-unstructured-doc-extraction` creates (`chunk_id`, `file_name`, `page_numbers`, `source_uri`). Offer to build one with it.

Show the user the index (`<catalog>.<schema>.<index_name>`), whether it has continuous updates, its `filter_values`, and its `corpus_description`.

## 2. Collect inputs

Ask once, listing every input from the SKILL.md Inputs table with its proposed default. If `forge` started this skill, the user may already have given some of them: confirm those instead of asking again. Derive the following and show them back to the user:

```
name                = <≤17 chars, [a-z0-9-]>           # app: agent-bricks-<name>; default: the index's name
```

## 3. Tooling and base skills

**Load:** `databricks-core` (profile selection and auth).

```bash
databricks --version                     # >= v1.11.0 (needed for `ai-gateway`)
uv --version
uv tool install "databricks-agentbricks>=0.5.0,<0.6"   # or: pip install "databricks-agentbricks>=0.5.0,<0.6"
agentbricks --version
databricks auth login --host <workspace-url> --profile <profile>   # only if the profile is invalid
agentbricks login --profile <profile>
uv run <skill>/scripts/check_base_skills.py      # base skills and forge-unstructured-doc-extraction are installed and new enough
```

Agent Bricks CLI is Beta, and no workspace setting is needed. Module 01 edits files generated by the 0.5 template, so keep the version below 0.6. If the install is blocked (no package index egress, for example), stop and take the fallback in the SKILL.md decision table.

`check_base_skills.py` compares the sibling skill folders with the versions recorded in `ucs.yaml`, including the `forge-unstructured-doc-extraction` skill under `requires`. If it exits non-zero, stop: the modules cite reference files that the installed skills don't have. Ask the user to install or update databricks-agent-skills (v0.2.27 or later) in the same skills directory, for example with `databricks aitools update`, and to install `forge-unstructured-doc-extraction` from databricks-skill-forge if it's missing. Mention any `newer` skills in your final report. They usually work, but the skill owner should re-certify against them.

## 4. Chat model

**Load:** `databricks-unity-gateway` `references/querying.md` (how `system.ai` names resolve).

```bash
# Confirm the default, system.ai.claude-sonnet-5-5 (Claude Sonnet 5.5), is listed. Don't guess other names.
databricks ai-gateway list-model-services --parent schemas/system.ai -o json --profile <profile>
```

Record `system.ai.claude-sonnet-5-5` as `chat_model`. Use a different model only if the user asks for one, or if Sonnet 5.5 isn't listed. In that case, pick from the list and tell the user why. On Azure Government, Azure China, and AWS GovCloud/DoD, `system.ai` isn't available yet. There, record the legacy endpoint `databricks-claude-sonnet-5-5` if `databricks serving-endpoints list` shows it.

## 5. Permissions

The user running the skill needs:

| On | Privilege |
|---|---|
| the index | `SELECT` (+ `USE CATALOG`/`USE SCHEMA`), for local testing and evaluation |
| workspace | create Databricks Apps |
| the chat model | `EXECUTE` on the `system.ai` model service |

Check with `databricks grants get-effective table <catalog>.<schema>.<index_name> --profile <profile>`. Report any missing privilege. Don't try to grant it. If the output is hard to read, **load** `databricks-unity-catalog` `references/1-access-control.md`.

## 6. Cost go-ahead

Summarize what each step creates, then wait for an explicit yes:

- **App:** `agent-bricks-<name>` compute while running, plus a Databricks-managed Lakebase Runtime Store and Session Store.
- **Model calls:** `<chat_model>` tokens for every question, during local testing, evaluation, and live use.
- **Evaluation (module 03):** one agent run and several judge calls per eval question.

The index and its job already exist and are billed by `forge-unstructured-doc-extraction`.

## 7. Write `doc-qa.json`

After the go-ahead, write the resolved values to `<workdir>/doc-qa.json`:

```json
{
  "index_state": "doc-index.json",
  "name": "<name>",
  "chat_model": "system.ai.claude-sonnet-5-5",
  "eval_set": "evals.jsonl",
  "completed": []
}
```

`index_state` is the path of `doc-index.json`, relative to `<workdir>`. Later modules add `experiment` (01) and `app_url` (02). Optional overrides: `num_results` (01, default 8), and a `corpus_description` that replaces the index's in the tool description.
