# Forge

Forge builds complete Databricks solutions from a plain-language request. This skill is the entry point: it matches the request to one Forge use-case skill, hands off to it, and offers a next step when that skill finishes. It doesn't build anything itself.

## Conventions

- `<forge>` is the folder that holds this SKILL.md. The use-case skills and the base skills are its siblings, for example `<forge>/../forge-doc-qa-agent`.
- `<workdir>` is where the use-case skills keep their state files and projects. Default: the current directory.
- Load only the use-case skill you hand off to. Don't read the others, or any base skill, to decide.

## 1. Resume

Before matching anything, check `<workdir>` for the state files in the Resume table, in its order. The first one found means a build is in progress or done. Unless the request clearly asks for something else, offer to continue it, and hand off to that skill (step 6). Its own Resuming section decides where to start.

## 2. Match the request

Match on what the user wants at the end, not on what they start from: every use case starts from documents in a volume.

- **An answer to questions** (a chatbot, an assistant, RAG, "chat with these files"): `forge-doc-qa-agent`. It builds the index itself when there isn't one, so don't send the user to the index first.
- **Something to search** (a retrieval or search index, a knowledge base, chunks and embeddings for another agent or app): `forge-unstructured-doc-extraction`.
- **Values in tables** (fields, entities, line items, classifying or splitting document packets, a review queue, extraction accuracy): `forge-structured-doc-extraction`.

A user can also name the use case, by its title, its skill name, or close to either ("doc QA", "structured extraction"). `forge-unstructured-doc-extraction` and `forge-structured-doc-extraction` differ by two letters, so when a user names one, confirm it by its title. When the request is just `/forge`, show the use-case titles with their "Choose it when" text, and ask which one.

## 3. Ask when it's ambiguous

When the request fits more than one use case, or none clearly ("process my PDFs", "do something with these contracts"), ask one question about the result the user wants, with the use cases as choices. Don't guess.

## 4. Two use cases in one request

Run one at a time. Start with the one whose output the other needs; otherwise, the one the user mentioned first. When it's done, offer the other. If both pipeline skills will process the same documents, give them different `prefix` values: each runs its own job on the volume.

## 5. No matching use case

Tell the user Forge has no use case for the request, and point to the base skill that covers it. Load that skill only if the user wants to continue with it.

| Request | Base skill |
|---|---|
| One AI function call or query, such as `ai_parse_document` on one file, or classifying a column | `databricks-ai-functions` |
| Vector search over a table, not documents | `databricks-vector-search` |
| Train, tune, or score an ML model | `databricks-ml-training` |
| Serve a model, or manage serving endpoints | `databricks-model-serving` |
| A dashboard | `databricks-aibi-dashboards` |
| A Genie space or agent over tables | `databricks-genie-agents` |
| A data app that isn't a document agent | `databricks-apps` |
| A batch or streaming data pipeline | `databricks-pipelines` |
| A job, or a bundle | `databricks-jobs`, `databricks-dabs` |
| Postgres or OLTP storage | `databricks-lakebase` |
| Anything else | Read the `description` of the installed `databricks-*` skills and pick the closest. If none fits, `databricks-docs` |

## 6. Hand off

1. Confirm that `<forge>/../<skill>/SKILL.md` exists, and that its `metadata.version` is at least the skill's minimum in the Use cases table. If it's missing or older, tell the user to install it from databricks-skill-forge into the same skills directory as this skill, and stop.
2. Tell the user, in one sentence, which use case you picked and why.
3. Read `<forge>/../<skill>/SKILL.md`, and follow it from its Workflow. What the user has already said (the volume path, an endpoint, names) counts toward its module 00 questions: confirm those answers there instead of asking again. Its preflight checks its own base skills and guardrails.
4. When it reaches its Done when, offer the Next step from the Use cases table, if there is one.

## Guardrails

- **Route; don't build.** This skill starts nothing billable and creates nothing. The use-case skill asks for its own confirmations.
- **One use-case skill at a time,** even when the request needs two (step 4).
- **Deprecated products:** Agent Bricks Knowledge Assistant and Agent Bricks Information Extraction are being deprecated. Don't build or suggest them. Redirect a request for a Knowledge Assistant to `forge-doc-qa-agent`, and one for Information Extraction to `forge-structured-doc-extraction`, with one sentence saying why.
- **Never ask for or store tokens.** The use-case skills use the user's CLI profile.
